# 给 Codex 的提示词

把下面整段复制给 Codex。先在【】里写清楚你的声线放在哪里、是什么形式。

---

你在我的另一台电脑上工作。任务：把 HakiShow 演示讲解视频的解说换成我提供的声线。画面、字幕、配乐、音效都保持不变，新配音与原配音的时间一比一对齐。

**材料**
- 仓库：https://github.com/1760139151lkh-ctrl/hakishow ，分支 `polish/cn-live-studio`
- 配音替换包：`deliverables/配音替换包/`。开始前先完整阅读其中的 `使用说明.md`
- 原视频：`deliverables/HakiShow-演示讲解视频.mp4`（116.000 秒，1920×1080，60 帧）
- 我的声线：【例如：RVC 模型 D:\voice\me.pth 和 me.index／参考音频 D:\voice\ref.wav／某语音合成服务的音色 ID，以及调用方式】

**步骤**
1. 克隆仓库并切到 `polish/cn-live-studio`，进入 `deliverables/配音替换包`。确认 Python 3.8+ 可用，运行 `pip install -r requirements.txt`。
2. 先做往返自检：`python replace_voice.py --full 原旁白-整轨.wav --out-dir 自检`。`自检/对齐报告.md` 里 31 个短句的起点、终点偏差都应为 0.0 毫秒。否则停下来，告诉我环境出了什么问题。自检通过后删除 `自检/`。
3. 生成新配音，二选一，能用 A 就用 A：
   - A. 我的声线是变声／声线转换模型：用它整轨处理 `原旁白-整轨.wav`。不要裁掉开头和结尾的静音，不要变速，输出为 `新声线整轨.wav`。然后运行 `python replace_voice.py --full 新声线整轨.wav`。
   - B. 我的声线是语音合成音色或真人录音：按 `旁白文本.txt` 一行一句生成 12 个音频，台词必须一字不改（画面里烧录了字幕）。文件名用编号 `n1、n2、n3、n4a、n4b、n4c、n5、n6、n7、n8、n9、n10`（依次对应第 1–12 行），放进 `我的配音/`。生成时让每句时长尽量接近 `旁白时间表.md` 里的“时长”，在逗号、句号处停顿。然后运行 `python replace_voice.py --voice-dir 我的配音`。
4. 阅读 `输出/对齐报告.md`，按下面的标准验收。不达标的句子，按报告里的提示重新生成（只重做不达标的句子），再运行一次：
   - 31 个短句的发声起点最大偏差：方式 B 不超过 5 毫秒；方式 A 不超过 17 毫秒，即不超过一帧；
   - 方式 B 中每个短句的变速比例都在 0.80–1.25 之间；
   - “需要留意”一节为空，或者只剩你试听后确认可以接受、并向我说明了理由的项目。
5. 抽查：从 `输出/新视频.mp4` 中截取 0:08–0:14、0:28–0:40、1:30–1:41 三段试听，确认没有爆音、吞字、重叠和明显的变速感。再用 ffprobe 确认视频时长仍为 116.000 秒，画面仍是 1920×1080、60 帧。
6. 交给我：`输出/新视频.mp4`、`输出/新混音.wav`、`输出/新旁白-整轨.wav`、`输出/对齐报告.md`。在回复里贴出报告中“逐短句对齐检查”的摘要行和“需要留意”一节，并说明用的是方式 A 还是 B。

**约束**
- 不要修改 `timing.json`、`背景声-无旁白.wav`、`原旁白-整轨.wav`、`replace_voice.py` 和原视频；不要重新渲染画面；不要改台词。
- 不要把输出文件、声线模型、参考音频或任何密钥提交到仓库，也不要推送。`输出/`、`自检/`、`我的配音/` 已被 `.gitignore` 忽略。
- 声线工具需要 API 密钥时，只放在本机环境变量里，不写进任何文件。
