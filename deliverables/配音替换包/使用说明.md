# 配音替换包 · HakiShow 演示讲解视频

用途：把演示视频的解说换成你自己的声线，画面、字幕、配乐和音效都不变。新配音会放回原配音的时间位置，并按短句对齐到画面里烧录的字幕：字幕出现的那一刻，就是这句话开口的那一刻。

> 只换声线，不改台词。画面里烧录了字幕，台词必须和“旁白文本.txt”一字不差。

## 包里有什么

| 文件 | 说明 |
|---|---|
| `背景声-无旁白.wav` | 配乐和音效，已去掉旁白；旁白处的音乐已经按原节奏压低。116.000 秒，48 kHz 立体声 |
| `原旁白-整轨.wav` | 原解说整轨，116.000 秒，从 0 秒起与视频完全对齐，48 kHz 单声道；适合作为声线转换的输入 |
| `原旁白-分句/` | 12 句原解说，文件名是编号（n1…n10） |
| `旁白文本.txt` | 12 句解说词，一行一句，第 N 行对应时间表中的序号 N |
| `旁白时间表.md`、`旁白时间表.csv` | 每句的开始、结束和时长，以及 60 帧、30 帧下的帧号；另有 31 个短句的时间，与画面字幕一致 |
| `timing.json` | 同样的时间数据，供脚本读取 |
| `replace_voice.py` | 自动对齐、混音并合成视频的脚本 |
| `给Codex的提示词.md` | 交给 Codex（或其他编程助手）在另一台电脑上执行的提示词 |

12 句的编号：n1、n2、n3、n4a、n4b、n4c、n5、n6、n7、n8、n9、n10（依次对应“旁白文本.txt”第 1–12 行）。

## 第一步：准备新配音（二选一）

### 方式 A：声线转换（推荐，时间天然一比一）

用你的声线模型，或任何支持“音频转音频／变声”的工具，处理 `原旁白-整轨.wav`，得到一条同样长度的新音频。处理时不要裁掉开头和结尾的静音，也不要改变速度。然后运行：

```
python replace_voice.py --full 新声线整轨.wav
```

声线转换不改变说话节奏，每个字都还在原来的位置。脚本会校正转换工具可能带来的整体延迟（最多 ±3 秒），再逐句做毫秒级微调，并按原配音逐句匹配响度。

也可以逐句转换 `原旁白-分句/` 里的 12 个文件。输出保持原文件名，放进一个文件夹，然后用方式 B 的命令。

### 方式 B：用你的声线逐句合成或录音

按 `旁白文本.txt` 逐句生成或录制 12 个音频，wav、mp3、m4a、flac 都可以。文件名用编号（`n1.wav`、`n4a.mp3`…）或行号（`01.wav`…`12.wav`），放进一个文件夹，例如 `我的配音/`，然后运行：

```
python replace_voice.py --voice-dir 我的配音
```

脚本按逗号、句号处的停顿把每句切成短句（全片共 31 个，与画面字幕一一对应）。每个短句的发声段会被伸缩到原配音同一短句的起止位置，并保持音高。

建议每句的语速尽量接近原配音（整句时长见时间表），在逗号、句号处自然停顿。报告里的变速比例在 0.80–1.25 之间时，基本听不出变速；超出这个范围时，报告会说明该加快还是放慢、大约多少，或者是哪一个短句的停顿节奏不同。

## 第二步：运行

需要 Python 3.8 或更高版本、numpy 和 ffmpeg：

```
pip install -r requirements.txt
```

已经安装 ffmpeg 并加入 PATH 时，可以不装 imageio-ffmpeg；也可以用 `--ffmpeg 路径` 指定。

输出都在 `输出/` 文件夹：

| 文件 | 说明 |
|---|---|
| `新视频.mp4` | 画面原样拷贝（不重新编码），换上新配音后的成片 |
| `新混音.wav` | 完整成品音轨：配乐、音效和新配音，已按原片相同的母带流程处理（−15 LUFS），116.000 秒 |
| `新旁白-整轨.wav` | 只有新配音，116.000 秒，从 0 秒起与视频对齐 |
| `对齐报告.md` | 每句的变速比例，以及 31 个短句的起点、终点偏差 |

其他参数：
- `--voice-gain 2`：新配音整体加 2 dB，负数为减小；
- `--allow-missing`：缺少的句子保留原配音；
- `--whole-line`：只按整句对齐；
- `--no-video`：只输出音频；
- `--video`：指定原视频；
- `--out-dir`：指定输出目录。

## 在必剪里使用

所有音轨都从 0 秒开始，和视频一样长（116.000 秒），所以在必剪里不需要手动对位，全部贴着时间线开头放就行。

**做法一（最简单）**：直接把 `输出/新视频.mp4` 导入必剪继续剪辑。

**做法二（想在必剪里调音量）**：
1. 导入原视频 `HakiShow-演示讲解视频.mp4`，放在时间线 0 秒处。把这段视频的音量调到 0，或者分离音频后删除原声。
2. 导入 `输出/新混音.wav`，放在音频轨的 0 秒处。
   如果想分别调整配乐和人声，改为导入 `背景声-无旁白.wav` 和 `输出/新旁白-整轨.wav` 两条，都放在 0 秒处。两条直接叠加的响度约为 −17 LUFS，比成品音轨小约 2 dB；成品音轨还做过轻微的软限幅和响度标准化。
3. 导出时选 1080P、60 帧，和原片一致。

不建议在必剪里手动逐句摆放：拖动精度受时间线帧格限制，也没法按短句对齐字幕。确实要手动摆放时，用“旁白时间表”里的“开始帧@60”或“开始帧@30”（看必剪工程的帧率）定位。

## 验证记录

已在本机用以下几种输入验证（结果来自“对齐报告.md”）：

| 输入 | 结果 |
|---|---|
| 原旁白本身（往返自检） | 31 个短句起点、终点偏差均为 0.0 毫秒；新混音与原片母带逐采样比较，残差 −76.8 dB（即 16 位量化误差级别） |
| 原旁白整体延迟 137 毫秒 | 自动校正 +137.0 毫秒，31 个短句偏差均为 0.0 毫秒 |
| 原旁白升调 12% 并延迟 137 毫秒（模拟声线转换） | 短句起点最大偏差 13.4 毫秒，不到一帧（16.7 毫秒） |
| 另一种声音（男声）逐句合成，每句语速在 −18%～+15% 之间故意打乱 | 31 个短句起点最大偏差 3.6 毫秒，终点最大偏差 34 毫秒；有 4 句的变速比例超出 0.80–1.25，报告给出了重新生成的建议 |
