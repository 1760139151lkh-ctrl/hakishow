# 配音替换包 · HakiShow 演示讲解视频

用途：把演示视频的解说换成你自己的声线，画面、字幕、配乐和音效都不变。新配音会放回原配音的时间位置，并按短句对齐到画面大字和 SRT 字幕：字幕出现的那一刻，就是这句话开口的那一刻。

> 只换声线，不改台词。画面里的大字按台词逐字出现，台词必须和“旁白文本.txt”一字不差。

## 包里有什么

| 文件 | 说明 |
|---|---|
| `背景声-无旁白.wav` | 配乐和音效，已去掉旁白；旁白处的音乐已经按原节奏压低。118.000 秒，48 kHz 立体声 |
| `原旁白-整轨.wav` | 原解说整轨，118.000 秒，从 0 秒起与视频完全对齐，48 kHz 单声道；适合作为声线转换的输入 |
| `原旁白-分句/` | 20 句原解说，文件名是编号（v01…v20） |
| `旁白文本.txt` | 20 句解说词，一行一句，第 N 行对应时间表中的序号 N |
| `旁白时间表.md`、`旁白时间表.csv` | 每句的开始、结束和时长，以及 60 帧、30 帧下的帧号；另有 44 个短句的时间，与画面大字和 SRT 字幕一致 |
| `timing.json` | 同样的时间数据，供脚本读取 |
| `replace_voice.py` | 自动对齐、混音并合成视频的脚本 |
| `给Codex的提示词.md` | 交给 Codex（或其他编程助手）在另一台电脑上执行的提示词 |

20 句的编号：v01、v02……v20（依次对应“旁白文本.txt”第 1–20 行）。

## 第一步：准备新配音（二选一）

### 方式 A：声线转换（推荐，时间天然一比一）

用你的声线模型，或任何支持“音频转音频／变声”的工具，处理 `原旁白-整轨.wav`，得到一条同样长度的新音频。处理时不要裁掉开头和结尾的静音，也不要改变速度。然后运行：

```
python replace_voice.py --full 新声线整轨.wav
```

声线转换不改变说话节奏，每个字都还在原来的位置。脚本会校正转换工具可能带来的整体延迟（最多 ±3 秒），再逐句做毫秒级微调，并按原配音逐句匹配响度。

也可以逐句转换 `原旁白-分句/` 里的 20 个文件。输出保持原文件名，放进一个文件夹，然后用方式 B 的命令。

### 方式 B：用你的声线逐句合成或录音

按 `旁白文本.txt` 逐句生成或录制 20 个音频，wav、mp3、m4a、flac 都可以。文件名用编号（`v01.wav`、`v12.mp3`…）或行号（`01.wav`…`20.wav`），放进一个文件夹，例如 `我的配音/`，然后运行：

```
python replace_voice.py --voice-dir 我的配音
```

脚本按逗号、句号处的停顿把每句切成短句（全片共 44 个，与 SRT 字幕一一对应）。每个短句的发声段会被伸缩到原配音同一短句的起止位置，并保持音高。

建议每句的语速尽量接近原配音（整句时长见时间表），在逗号、句号处自然停顿。报告里的变速比例在 0.80–1.25 之间时，基本听不出变速；超出这个范围时，报告会说明该加快还是放慢、大约多少，或者是哪一个短句的停顿节奏不同。

## 第二步：运行

需要 Python 3.8 或更高版本、numpy 和 ffmpeg：

```
pip install -r requirements.txt
```

已经安装 ffmpeg 并加入 PATH 时，可以不装 imageio-ffmpeg；也可以用 `--ffmpeg 路径` 指定。

输出都在 `输出/` 文件夹：

| 文件 | 说明 |
|---|---|
| `新视频.mp4` | 画面原样拷贝（不重新编码），换上新配音后的成片 |
| `新混音.wav` | 完整成品音轨：配乐、音效和新配音，已按原片相同的母带流程处理（−14 LUFS），118.000 秒 |
| `新旁白-整轨.wav` | 只有新配音，118.000 秒，从 0 秒起与视频对齐 |
| `对齐报告.md` | 每句的变速比例，以及 44 个短句的起点、终点偏差 |

其他参数：
- `--voice-gain 2`：新配音整体加 2 dB，负数为减小；
- `--allow-missing`：缺少的句子保留原配音；
- `--whole-line`：只按整句对齐；
- `--no-video`：只输出音频；
- `--video`：指定原视频；
- `--out-dir`：指定输出目录。

## 在必剪里使用

所有音轨都从 0 秒开始，和视频一样长（118.000 秒），所以在必剪里不需要手动对位，全部贴着时间线开头放就行。

**做法一（最简单）**：直接把 `输出/新视频.mp4` 导入必剪继续剪辑。

**做法二（想在必剪里调音量）**：
1. 导入原视频 `HakiShow-演示讲解视频.mp4`，放在时间线 0 秒处。把这段视频的音量调到 0，或者分离音频后删除原声。
2. 导入 `输出/新混音.wav`，放在音频轨的 0 秒处。
   如果想分别调整配乐和人声，改为导入 `背景声-无旁白.wav` 和 `输出/新旁白-整轨.wav` 两条，都放在 0 秒处。两条直接叠加的响度约为 −16 LUFS，比成品音轨小约 2 dB；成品音轨还做过轻微的软限幅和响度标准化。
3. 导出时选 1080P、60 帧，和原片一致。

不建议在必剪里手动逐句摆放：拖动精度受时间线帧格限制，也没法按短句对齐字幕。确实要手动摆放时，用“旁白时间表”里的“开始帧@60”或“开始帧@30”（看必剪工程的帧率）定位。

## 毫秒级对齐：自己动手检查

换完声线后，按下面三步确认每一个字都对得上，不需要靠耳朵猜：

1. **看数字**：打开 `输出/对齐报告.md`，找到“共 44 个短句：发声起点最大偏差 … 毫秒”这一行。起点最大偏差不超过 17 毫秒（60 帧视频的一帧），画面大字和字幕就与开口完全同步。
2. **看变速**：报告第一张表的“变速比例”在 0.80–1.25 之间时听不出变速；超出时，“需要留意”一节会写明是哪一句、该加快还是放慢多少，或是哪个短句的停顿节奏不同。只重做这几句，再运行一次脚本即可。
3. **抽查三段**：在 `输出/新视频.mp4` 里试听 0:00–0:12（开场大字逐字出现）、0:29–0:42（喷火、爱心、盲盒三连）、1:34–1:44（技术段长句），确认没有爆音、吞字和重叠。

需要在必剪里手动摆放某一句时，用“旁白时间表”的“开始帧@60”（60 帧工程）或“开始帧@30”（30 帧工程）定位，不要靠拖动目测。

## 验证记录

2026 年 11 月 23 日按当前时间表（118.000 秒，20 句，44 个短句）在本机实测，数字来自各次的“对齐报告.md”：

| 输入 | 结果 |
|---|---|
| 原旁白本身（往返自检，`--full 原旁白-整轨.wav`） | 44 个短句的起点、终点偏差全部为 0.0 毫秒，所有句子变速比例为 1.00 |
| 原旁白升调 12% 并整体延迟 137 毫秒（模拟声线转换） | 自动整体校正 +127.0 毫秒，再逐句微调；44 个短句起点最大偏差 10.7 毫秒、平均 4.0 毫秒，终点最大偏差 6.9 毫秒、平均 2.3 毫秒，全部在一帧以内 |
| 另一种声音逐句合成（Edge“云希”，默认语速，未刻意对齐，`--voice-dir`） | 44 个短句起点最大偏差 10.0 毫秒、平均 2.6 毫秒；终点最大偏差 57.6 毫秒、平均 18.0 毫秒。云希比原配音慢约 6%，有 8 句的局部变速比例超出 0.80–1.25，报告逐句给出了“放慢约 x%”或“逗号处停顿与原配音不同”的重做建议 |

结论：方式 A（声线转换）可以直接达到逐帧对齐；方式 B 的起点同样能对齐到一帧以内，但要让每句的语速和停顿接近原配音，按报告提示重做个别句子后，变速才会完全听不出来。
