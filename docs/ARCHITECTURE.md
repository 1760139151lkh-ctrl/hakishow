# 架构

HakiShow 由浏览器应用和可选的本地工作室服务组成。同一套界面既可以在没有服务时展示随附素材，也可以借助服务提供账户、上传素材和异步图像处理。

## 组成部分

| 层次 | 主要文件 | 职责 |
|---|---|---|
| 应用入口 | `web/index.html`、`web/js/main.js`、`web/js/copy.js` | 启动、中文界面文案和应用生命周期 |
| 页面与可复用控件 | `web/js/screens/`、`web/js/ui/`、`web/css/`（`app.css` 基础样式，`live.css`、`studio.css`、`intro.css` 分页面样式） | 实时视图、工作室、结果、作品库、个人资料、首次引导和弹出面板 |
| 风格与区域 | `web/js/presets.js`、`web/js/parts.js` | 风格主题与提示词、默认值、细节选项、可选区域和编辑选项 |
| 浏览器状态 | `web/js/core/data.js`、`db.js`、`undo.js`、`shots.js`、`nav.js`、`bus.js` | IndexedDB 记录、草稿、偏好、版本链、撤销／重做、导航和事件 |
| 服务连接 | `web/js/core/api.js`、`generate.js` | 服务发现、上传、图像操作轮次、进度、取消、重试和本地备用处理 |
| 交互式编辑 | `web/js/studio/` | 工具面板、蒙版、区域选择、颜色预览和对话 |
| 本地相机与视觉处理 | `web/js/live/`、`web/js/core/face.js` | 相机生命周期、人脸跟踪（`tracker.js`）、人脸网格（`mesh.js`）、多通道渲染（`renderer.js`）、滤镜（`looks.js`）、人像分割（`segment.js`）、特效包与触发（`effects.js`）、三维挂件与动作特效（`overlay.js`）、音效（`sound.js`） |
| 工作室 HTTP 服务 | `likeness/server.py` | 浏览器应用分发，以及访问、账户、素材、图像任务和同步接口 |
| 工作室持久化存储 | `likeness/accounts.py`、`store.py`、`paths.py` | 运行数据目录下的账户，以及按账户隔离的文件和记录 |
| 任务执行 | `likeness/turns.py`、`jobs.py`、`brief.py`、`estimates.py` | 请求解析、队列、进度、取消、任务说明（用户可见文字为中文）和估算 |
| 图像引擎 | `likeness/engines/` | 模拟器、已配置的图像接口，以及可选的本地命令式引擎 |
| 创意建议 | `likeness/rooms.py` | 风格／创作空间定义，以及具有可用备用方案的中文建议 |

## 一轮图像编辑

1. 浏览器在当前草稿中保存原始图像、选定风格、参数值和选定区域。
2. 对于依赖工作室服务的编辑，浏览器通过 `/api/assets` 上传源图像和所有区域蒙版。
3. 浏览器将操作意图、源素材引用和编辑指令提交到 `/api/turns`。
4. 服务器将这一轮操作加入工作队列。所选引擎接收输入图像和一份任务说明。
5. 浏览器监听任务事件或轮询任务接口。用户可以取消正在执行的请求，并重试失败或已停止的请求。
6. 结果成为新的版本。浏览器保留源图像和先前版本，更新作品库，并将符合条件的记录同步到当前账户。

模拟器会演练这一控制流程，并明确标注其替代输出。静态展示使用随附的示例结果或本地预览，不会声称某个外部模型已经完成生成。

## 主要接口分组

| 接口 | 用途 |
|---|---|
| `GET /api/health`、`GET /api/catalog` | 工作室能力、引擎状态和可用配置 |
| `POST /api/assets`、`GET /api/assets/{id}` | 存储和获取归账户所有的图像与蒙版 |
| `POST /api/turns` | 开始图像生成、编辑或变化版本任务 |
| `GET /api/jobs/{id}`、`GET /api/jobs/{id}/events` | 轮询状态或接收服务器发送的进度事件 |
| `POST /api/jobs/{id}/cancel` | 请求取消 |
| `GET /api/history` | 获取当前账户的结果历史 |
| `GET /api/me`、`POST /api/auth/*` | 访客／成员身份、注册、登录、退出和个人资料 |
| `GET /api/sync`、`POST /api/sync` | 增量交换浏览器记录和偏好设置 |
| `POST /api/styles` | 请求创意风格定义 |

在已配置的访问控制范围内，运行中的服务通过 `/api/docs` 和 `/api/openapi.json` 提供其实际接口规范。

## 浏览器持久化与账户

浏览器使用名为 `hakishow` 的 IndexedDB 数据库，以及 `hakishow.*` 偏好设置键。本地记录支持草稿、作品、源图像、收藏、偏好和撤销状态。访客作品可以随访客登录而转入账户。服务端拥有的素材与当前账户关联；测试覆盖隔离和同步。

运行数据默认放在 `private/` 中。`LIKENESS_HOME` 可以指定其他数据目录。配置先读取已提交到版本控制的 `studio.toml`，再读取运行目录中的 `studio.toml`；`.env.local` 提供本地环境值。可分发的源代码包不需要包含任何运行数据。

## 实时相机渲染管线

实时相机分为三层：全局基础层（美颜、美型、滤镜，任何特效下都生效）、实时特效层（33 个特效包）和云端创作层（拍照后生成艺术肖像）。每一帧按以下顺序处理：

1. **检测**：在同一帧内调用 MediaPipe 人脸关键点检测（478 个点与表情系数）；开启背景时调用人像分割。检测与绘制使用同一帧，特效不会落后于人脸。
2. **平滑**：`tracker.js` 把关键点拆为刚体运动（中心、角度、尺度）与人脸坐标系中的局部形状，分别用 One Euro 滤波平滑，静止时稳定、快速运动时跟手；由三维关键点求出人脸坐标轴与偏航、俯仰、翻滚角。
3. **网格形变**：`mesh.js` 以官方三角剖分为基础，加上脸外三圈过渡环、眼部与嘴部扇形，在人脸坐标系（以瞳距为单位）中计算平滑位移场，实现瘦脸、大眼、V 脸、瘦鼻与大头等效果；侧脸时按角度自动减弱。
4. **合成**（WebGL）：形变通道写入皮肤权重 → 特征蒙版（唇、腮红、分割）→ 半分辨率双边滤波两次 → 八分之一分辨率模糊 → 合成（高低频磨皮、美白、红润、柔光妆容、背景虚化或场景替换、三维查找表滤镜）→ 风格通道（色调、色调分离、描边、半调、轮廓光、霓虹辉光、泛光、扫描线、暗角、颗粒、像素化、冲击缩放、原图对比）。
5. **叠加**（Canvas 2D）：`overlay.js` 用人脸三轴的弱透视投影把贴纸“戴”在头上，并绘制动作特效、粒子与风格边框；`live.js` 的状态机以迟滞阈值和冷却时间识别张嘴、微笑、挑眉、转头并触发特效与音效。

自动构图根据人脸大小与位置缓慢推拉镜头，使人脸位于顶栏与底部面板之间的取景区中央。性能不足时自动降低渲染分辨率，并在检测耗时过高时隔帧检测。

用图像模型连续变换每一帧视频仍是后续研究方向；当前的“实拍”成片在本地完成，“AI 艺术”成片在拍照后由云端生成。

## 构建与安装

`tools/build.mjs` 将原生浏览器模块打包到 `workstation/bundle/`；它会记录输入版本，以便识别过期的构建包。源代码仍位于 `web/`。`tools/serve.mjs` 运行静态展示；Python 服务器同时提供应用及其接口。

网页应用清单和服务工作线程提供现有的安装／缓存行为。新一轮依赖服务端的生成仍需要已配置的服务和引擎。不要把缓存的界面等同于能够离线使用托管生成。

## 扩展边界

通过预设数据结构新增风格，通过区域定义新增编辑选项，通过引擎接口新增引擎，并通过已有导航和状态机制新增页面。保留中文的成功／错误／备用处理消息，每次行为变更都要更新相关测试和文档。在增加其他框架或服务之前，先使用已有扩展接口。
