## 2. 背景与意义

人们通常希望获得个性化头像，而不想学习复杂的编辑软件。他们需要尝试风格、保持本人相似度、修改特定细节、比较版本并保存结果。单一的通用滤镜往往不够；有用的工具既应提供容易上手的第一步，也应支持精确的后续控制。

HakiShow 将快捷的实时相机入口与照片工作室结合起来。其视觉风格随所选样式变化，而一致的编辑控件让探索过程易于预期。自然语言请求减轻了学习专业编辑术语的负担。选择画笔和面部部位控件，让用户能够表达应当修改的位置。

直接价值在于提供连贯、愉快的人像创作流程。学习价值在于让团队积累界面设计、图像处理、异步服务、状态持久化、团队合作、测试以及解释工程决策的经验。更完整的实时艺术变换是持续研究与开发的目标。

## 3. 需求与设计

### 核心流程

1. 选择示例、上传照片，或使用可用的相机。
2. 选择 33 个风格预设之一，或描述一种新风格。
3. 调整风格强度、相似度、细节丰富度和美化程度；选择格式与画质。
4. 应用细节选项，或通过面部部位控件或绘制选择区域。
5. 请求生成或编辑。跟踪进度，必要时取消，并从失败中恢复。
6. 用英语描述另一项修改，比较版本，并返回较早版本。
7. 保存或导出结果，并通过作品库再次查看。

### 配套能力

保留收藏、偏好、草稿、撤销／重做、版本历史、美术示例、账户归属和增量同步。帮助、加载、空状态、权限和失败状态都是体验的一部分。

浏览器使用本地相机渲染、面部跟踪和受支持的区域预览。工作室服务处理账户数据、上传素材、异步生成任务和已配置的图像引擎。静态展示、模拟器和已配置的托管生成保持为不同模式，并具有清晰标签。

### 用户角色与权限

| 角色 | 预期操作 |
|---|---|
| 访客 | 探索风格和示例；创建浏览器本地草稿和预览；在可用时使用已配置工作室的访客会话 |
| 注册创作者 | 管理个人上传、结果、收藏和偏好；跨设备访问自己的同步记录 |
| 工作室所有者 | 配置工作室服务、访问设置和服务商连接；维护应用环境 |

账户数据和作品记录应保持与相应用户关联。独立管理后台是可选项，不属于当前基线。只有在能够改善人像创作流程时，才开发额外的搜索、统计或图表功能。

### 技术方案

浏览器应用采用原生 JavaScript 模块、CSS 和网页应用编程接口。Python FastAPI 工作室提供 HTTP 接口和异步任务更新。MediaPipe 素材支持本地面部和头发处理；美术素材随包提供，以支持独立演示。当前实现使用本地服务存储和账户记录；当团队有具体需求时，可以再选择未来的数据库或托管部署方案。

模块边界和数据流见[架构](ARCHITECTURE.md)，当前基线与未来目标的区别见[功能状态](FEATURE_STATUS.md)。
