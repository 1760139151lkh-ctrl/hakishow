# 后续开发与最终提交

从可运行的演示程序出发，为团队继续改善体验留下空间。将每一项必需的挑战内容与负责人、成果和可审查的完成条件关联起来。

## 1. 复现交接版本

**负责人：组长，组员1和组员2参与。** 在全新的项目文件夹中按照 `SETUP.md` 操作。运行静态展示和模拟器工作室。完整走一遍示例／上传、风格、调整、区域选择、对话、比较、作品库和导出流程。在判断还需要哪些验证之前，先阅读 `VALIDATION.md`。

完成条件：每位成员都能启动应用、解释各种模式、找到自己负责的模块，并演示主要流程。记录特定环境中的问题，修复阻碍演示的问题。

## 2. 确立预定图像服务

**负责人：组员2。** 配置为本次挑战选定的服务。检查基于用户自己图像的生成、相似度保持、特定蒙版编辑、变化版本、进度、取消、错误消息和恢复。保持示例与模拟器标签准确。

完成条件：所选引擎能够按照明确的配置步骤演示必需操作；对不支持的操作，提供可用替代方式或明确的下一项任务。

## 3. 改善艺术效果与编辑体验

**负责人：组员1，组员2协作。** 对照所要求的风格和局部修改检查真实输出。调整文案、默认值、区域反馈和比较方式。尝试少量效果突出的想法：连贯的人像系列、更清晰的区域预览、有引导的修改前后展示，或表现力更强的风格细节。保留已有风格和有用的原始素材。

完成条件：新用户无需开发者解释，即可得到结果、识别变化、修改细节并保存偏爱的版本。

## 4. 将实时效果推进为明确的里程碑

**负责人：组员2，组员1协作。** 在目标设备上分析现有相机流程的性能。测量帧率、交互延迟、启动情况、内存和跟踪稳定性。选择一种可实现的艺术效果，先完成从输入到输出的整体实现，再扩充效果目录。决定哪些处理在本地运行，哪些处理可以接受远程请求往返。

完成条件：一种有明确名称的效果具备可重复测量的数据、可见收益、稳定控件，以及在相机或计算能力不可用时的备用方案。完整的实时模型变换应通过这项工作成为已演示的能力，而不是附加在现有预览上的假设。

## 5. 整理全部五项最终交付物

| 必需项目 | 制作依据 | 最低完成条件 |
|---|---|---|
| 可运行源代码 | 当前项目、依赖锁定文件、安装和验证记录 | 能够全新安装，并演示主要流程 |
| 演示文稿 | 开题报告、使用场景、界面截图、架构和结果比较 | 覆盖全部挑战主题，并适合五分钟演示 |
| 项目介绍与成果报告 | 需求、决策、模块职责、成果和未来计划 | 完整的英语说明，团队角色一致，能力状态符合实际 |
| 带解说的演示视频 | 预先准备的示例／上传操作，展示可见的编辑过程和已保存结果 | 主要操作易于理解；具有英语解说或说明，能够可靠播放 |
| 贡献文档 | `TEAM.md`、模块成果和成员审查 | 完整记录每个人的具体工作及组长的 10 分制评价 |

现有开题报告和交接文档提供规划材料。选定最终演示版本之后，再制作最终演示文稿、录像和成果报告，使这些材料展示同一个应用及其成果。

## 6. 排练与审查

**负责人：组长。** 按照 `TEAM.md` 排练五分钟展示流程，再排练三分钟问答。确认每个人持有相同的最终文件。使用 30／30／30／10 评分标准审查外观与易用性、实用价值、完整性和创新性。吸收评审者和同伴的反馈。

完成条件：源代码、讲述内容、团队记录、幻灯片和录像保持一致；软件包易于获取和运行；对剩余研究问题有清晰认识。

## 开发智能体的工作方式

将 `AGENTS.md` 和上述文档作为项目任务说明。检查并复用已实现的工作，完成必需成果，验证变更后的行为，并同步维护文档。提出具体的创意方案，将有用方案落实为可见的改进。必需提交材料和主要用户流程始终是完成目标。

面向后续远程开发会话的详细对话提示词，有意不放入本次交接包。项目已经提供那些后续对话所需的事实、责任分工和完成标准。
